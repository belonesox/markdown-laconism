Markdown стал доминирующей плоской разметкой, с нулевой кривой входа, известной всем околоайтишникам и ИИ, и по сути похоронил массовое использование 
`SGML`/`[X]HTML`/`Dita`/`LaTeX`/`AsciiDoc`/`RST`/`[Media]Wiki` и прочих, возможно более умных разметок.

Может это и к лучшему, поддержка Markdown в `code-server`, с LaTeX-формулами-графами и кучей других возможностей позволяет эффективно делать и техдокументацию и обучающие материалы, не заморачиваясь с проблемами страничной «версткой книг», и не используя монструозные решения типа `pandoc`.

Особенно, учитывая что в markdown можно вставлять практически произвольные блоки HTML-кода, если нужно что-то особое, интерактивное или визуальное.

Но некоторые вещи в markdown можно улучшить «не отходя от кассы» 
- не изобретая новых расширений (pandoc-подход)
- не добавляя новых элементов разметки
- а расширяя идеи, уже заложенные в markdown, позволяя той же разметкой делать что-то компактней и лучше.


#### Включение видео и markdown-документов

Например, в образовательных материалах и технической документации полезно вставлять маленькие иллюстрирующие медиаролики — как картинки, только живые, из мира Гарри Потера.

Но классический подход с `<div><video …>…</video>` тегами очень монструозен, ведь таких картинок может быть много.

Мы расширяем функциональность «включения» c учетом markdown расширения `image size`
что можно включать не только картинки
`![ALT]`&#8203;`(путь-к-картинке.png =ШиринаxВысота)`
но и видео `![класс и стили]`&#8203;`(путь-к-видео.webm =ШиринаxВысота)`

Также больным местом является трансклюзия других markdown-документов — то что есть во всех практически остальных разметках  (LaTeX/SGML Docbook/MediaWiki/RST/…) тут из коробки нет. А включать хочется не только Markdown-документы, но и какие-то проектные артефакты, типа вырезок из файлов конфигов, логов, 
и немаловажное — включение таблиц (включая форматирование и раскраску), которых проще держать и вести в CSV или XLXS, потому что таблицы в Markdown все-таки боль.

Такую же «трансклюзию», мы тоже получаем, расширяя семантику «включения»
`![класс и стили]`&#8203;`(путь-к-markdown-документу.md)`
- Причем если указывать абсолютный путь, мы получим включение относительно папки проекта `${workspaceFolder}`

Далее тонкости включения других артефактов.

#### Включение таблиц

Поместите ссылку-включение на локальный CSV или XLSX в отдельный абзац. 
Путь отсчитывается от Markdown-файла, в котором записана ссылка.

<pre>`!&#91;rows=0;-3:, cols=0;2:4, trans](./current-portfolio.csv)

!&#91;sep=semicolon, header=none](./measurements.csv)

!&#91;sheet="Портфель, EUR", rows=0:5, styles](./portfolio.xlsx)`</pre>

- `rows` и `cols` выбирают строки и столбцы исходной таблицы, условно как питоновые слайсы. 
    - индексы начинаются с нуля, правая граница среза исключается, отрицательные индексы считаются с конца. 
    - `;` соединяет выборки в указанном порядке, но повторяющиеся индексы попадают в результат один раз.
    - если выбрана строка `0`, её ячейки служат заголовками.
        - `header=none` делает их обычными ячейками.


-  Флаг `trans` меняет строки и столбцы местами после выборки. 
    - В первом примере слева получатся названия полей, справа — значения трёх последних записей.

- Для CSV используется UTF-8. Разделитель по умолчанию — запятая. 
    - доступны `sep=comma`, `sep=semicolon`, `sep=tab` и `sep=dblquote`
- Для XLSX по умолчанию берётся первый лист. 
    - Параметр `sheet` выбирает лист по имени. 
    
- Даты и числа выводятся с учётом формата ячейки, а формулы — с последним сохранённым результатом. `⁇` — результат отсутствует. 
- Флаг `styles` приносит из XLSX таблиц,  жирный шрифт, курсив, горизонтальное выравнивание и явно заданные RGB-цвета текста и сплошной заливки.
- После обновления включаемых файлов, обновляется и предпросмотр.
- Для эффективности вырезки кэшируются в `.vscode/.cache/md-laconism/` — не забудьте исключить в `.gitignore`.

### Включение текстового файла как блока кода

Также, как с таблицами, держите включение отдельным абзацем, и относительный путь считается от самого вложенного файла. Сохраняет отступы, пустые строки и символы Markdown. 

<pre>
!&#91;](./example.txt)

!&#91;](./diagram.py)

!&#91;type=yaml](./config.yaml)

!&#91;type=mermaid](./diagram.generated)

!&#91;type=text](./diagram.py)
</pre>

- Язык подсветки 
    - по расширению файла
        - Python для `.py` и YAML для `.yml`…
    - или по имени
        - `Makefile`, `Dockerfile`…
    - иначе без подсветки, или явно указать `type=язык` 
    (выбирает тот же обработчик, что и у блока кода Markdown)
        - `type=mermaid` превращает исходник в диаграмму, 
        - `type=text` показывает даже Python без раскраски
- Поддерживаются UTF-8 и UTF-16 с маркером BOM 

Также, как с включением таблиц, есть параметры 
`rows` и `cols`, только теперь имеются в виду строки и колонки текстового файла — это удобно чтобы включать вырезки-примеры из больших логов или конфигов.
- Пустые строки учитываются. 
- Завершающий перевод строки дополнительной строки не создаёт.
- Для `cols` единица счёта — кодовая точка Unicode. 
- Табуляция занимает одну позицию. 
- В короткой строке отсутствующие позиции пропускаются. 
- Подсветка применяется к готовой выборке.

<pre>!&#91;rows=10:15](./example.py)

!&#91;type=text, rows=0;-3:, cols=8:](./server.log)</pre>

- Первый пример покажет строки с 11-й по 15-ю с подсветкой Python. 
- Второй — первую строку и три последние, начиная с девятого символа каждой строки. 

Для Mermaid достаточно одного обработчика в предпросмотре. В VS Code со встроенной поддержкой диаграмм используйте её. В версиях VS Code и code-server без встроенной поддержки установите `bierner.markdown-mermaid`.


### Ссылки на соседние файлы и разделы

Чтобы сослаться на файл и показать читателю его путь, запишите путь в обратных кавычках. Признак такой ссылки — начало `./`. Если нужно подняться на уровень выше, сохраните этот префикс и начните с `./../`.

```markdown
- Отправка заявки — `./../logic/portfolio/neos_transport.py`
- Формирование приказов QUIK — `./../logic/portfolio/quik_orders.py`
- Подробней → `./03_markowitz.md`
```

В предпросмотре первые две ссылки открывают Python-файлы, третья ведёт к Markdown-файлу. 
Поразумевается, что у вас есть механизм экспорта HTML-превью Markdown-файлов в HTML-файлы лежащие рядом, например расширение `Freeze Markdown`. Поэтому, у третьей ссылки адрес становится `./03_markowitz.html`, что позволит пользователю переходить по ссылка в IDE по Markdown-документации, а при просмотре готовой HTML-документации — по HTML-файлам.

### Ссылка на фрагмент исходника и включение того же фрагмента

Одна из важнейших задач технической документации — кратко описывать архитектуру-идеи, и делать ссылки на код, конфиги, артефакты. Причем делать так, чтобы можно было легко переходить к нужным местам этих артефактов из самого markdown-файла vscode/code-server, так и из сгенеренной документации.

Причем даже есть HTML-стандарт [Text_fragments](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment/Text_fragments) ссылок «на блоки» в файле, и тут мы придерживаемся его,  

Добавьте к пути `#:~:text=начало`, чтобы сослаться на фразу, или `#:~:text=начало,конец`, чтобы выбрать текст от первой фразы до второй включительно. Например, в обзоре архитектуры можно дать ссылку на метод, а рядом показать только ту часть конфигурации, которая нужна читателю.
Теперь это работает и в ссылках, и в ссылках-трансклюзиях, позволяя включать прямо блоки текста из кода-конфигов внутрь самой документации.

```markdown
Расчёт начинается в [методе run_hist](../logic/opt_algo.py#:~:text=def%20run_hist).

Реестр торгуемых облигаций хранится в конфигурации проекта.

![](../logic/portfolio/config.py#:~:text=TRADABLE_BONDS,%7D)
```
- Включение занимает отдельный абзац. 
- В этом примере блок начинается с `TRADABLE_BONDS` и заканчивается первой следующей закрывающей скобкой `}` (в адресе — `%7D`). 
- Справа над блоком виден весь путь из включения — `../logic/portfolio/config.py ↗`. Щелчок открывает тот же фрагмент в исходнике. 
    - Чтобы убрать ссылку над конкретным блоком, укажите `source_link=0`.

```markdown
![source_link=0](../logic/portfolio/config.py#:~:text=TRADABLE_BONDS,%7D)
```

Параметры `rows` и `cols` применяются к уже найденному фрагменту. Ссылка над блоком по-прежнему ведёт к диапазону, указанному в адресе. При включении без `#:~:text=` она открывает файл целиком.

И да, чтобы файлы с кодом не скачивались, а показывались в броузере и подсвечивался заказанный блок, надо настроить веб-сервер отдавать исходники как `text/plain; charset=utf-8`.

#### Тонкости поиска — как выбрать одно из повторяющихся совпадений

Поиск игнорирует регистр и берёт первое совпадение. Уточните его соседним текстом. Контекст может примыкать вплотную или отделяться пробельными символами. В выделение и в цитируемый блок попадает только искомый текст.

| Фрагмент адреса | Что будет выделено |
| --- | --- |
| `#:~:text=foo-,bar` | `bar`, непосредственно перед которым стоит `foo`. |
| `#:~:text=foo,-bar` | `foo`, непосредственно после которого стоит `bar`. |
| `#:~:text=prefix-,start,end,-suffix` | Диапазон от `start` до `end` с контекстом `prefix` слева и `suffix` справа. |

Используйте одну директиву `text=` на ссылку. Внутри искомых фраз и контекста кодируйте пробел как `%20`, запятую как `%2C`, амперсанд как `%26`, дефис как `%2D`. Запятые и дефисы, которые задают границы контекста в самой директиве, оставляйте как в примерах.

### Ссылка на Git-коммит через `diff://`

Когда нужно показать, каким изменением появилось описываемое поведение, укажите хеш коммита в Markdown-ссылке. 
Это бывает полезно при написании-презентации сделанной работы, код-ревью разборов и т.п., особенно когда git-проект не лежит в системе с веб-интерфейсом, или сам коммит еще не опубликован там.

Например, эта ссылка относится к истории самого расширения.

```markdown
[Изменения для включения таблиц и текстовых файлов](diff://a24f042)
```

В редакторе Markdown сделайте Ctrl+клик по адресу `diff://a24f042`. Расширение откроет виртуальный документ только для чтения с подсветкой `diff`. Внутри — сведения о коммите, его сообщение и текст изменений по файлам со строками `+` и `-`, как в выводе `git show --color=never a24f042`.

Для своего проекта подставьте полный хеш или его однозначное сокращение из `git log --oneline`. Git запускается из **первой папки открытой рабочей области**, в том числе если Markdown-файл лежит в другой папке. Коммит должен быть доступен в истории этого репозитория. Если рабочая папка не открыта или Git не находит коммит, в виртуальном документе появится сообщение об ошибке.

#### Тот же коммит в предпросмотре и в опубликованном HTML

В Markdown Preview щелчок открывает страницу коммита на Git-хостинге. Freeze Markdown записывает в HTML обычный веб-адрес, поэтому читателю достаточно браузера и доступа к репозиторию. При рендеринге расширение читает локальные настройки Git. Конечно, для веб-просмотра коммит должен быть опубликован в выбранном репозитории.

Расширение ищет репозиторий от каталога Markdown-файла, в котором записана ссылка. Сначала проверяет адрес для чтения (fetch URL) у `origin`, затем — у остальных remote, пока не найдёт GitHub или GitLab по имени хоста или remote. Например, если `origin` ведёт в локальный каталог, а `upstream` — на GitLab, ссылка ведёт на `upstream`. Если Git может разрешить сокращённый хеш локально, в веб-адрес подставляется полный хеш. Иначе сохраняется хеш из ссылки.

| Адрес remote | Веб-адрес коммита |
| --- | --- |
| `git@github.com:team/project.git` | `https://github.com/team/project/commit/{commit}` |
| `ssh://git@gitlab.example.org:2222/team/subgroup/project.git` | `https://gitlab.example.org/team/subgroup/project/-/commit/{commit}` |

Для другого хостинга, SSH-псевдонима или выбора конкретного зеркала задайте шаблон в `.vscode/settings.json` проекта. Он имеет приоритет над автоматическим выбором. Укажите полный HTTP- или HTTPS-адрес страницы коммита, заменив хеш на `{commit}`.

```json
{
  "markdown-laconism.commitUrlTemplate": "https://git.example.org/team/project/changeset/{commit}"
}
```

Пустое значение включает автоопределение. Если веб-адрес определить не удалось, в предпросмотре и при экспорте сохраняется `diff://`. Задайте шаблон и повторите экспорт, чтобы обновить ссылки в уже сохранённом HTML.
