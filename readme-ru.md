Markdown стал доминирующей плоской разметкой, с нулевой кривой входа, известной всем околоайтишникам и ИИ, и по сути похоронил массовое использование 
`SGML`/`[X]HTML`/`Dita`/`LaTeX`/`AsciiDoc`/`RST`/`[Media]Wiki` и прочих, возможно более умных разметок.

Может это и к лучшему, поддержка Markdown в `code-server`, с LaTeX-формулами-графами и кучей других возможностей позволяет эффективно делать и техдокументацию и обучающие материалы, не заморачиваясь с проблемами страничной «версткой книг», и не используя монструозные решения типа `pandoc`.

Особенно, учитывая что в markdown можно вставлять практически произвольные блоки HTML-кода, если нужно что-то особое, интерактивное или визуальное.

Но некоторые вещи в markdown можно улучшить «не отходя от кассы» 
- не изобретая новых расширений (pandoc-подход)
- не добавляя новых элементов разметки
- а расширяя идеи, уже заложенные в markdown, позволяя той же разметкой делать что-то компактней и лучше.


Например, в образовательных материалах и технической документации полезно вставлять маленькие иллюстрирующие медиаролики — как картинки, только живые, из мира Гарри Потера.

Но классический подход с `<div><video …>…</video>` тегами очень монструозен, ведь таких картинок может быть много.

Мы расширяем функциональность «включения» c учетом markdown расширения `image size`
что можно включать не только картинки
`![ALT]`&#8203;`(путь-к-картинке.png =ШиринаxВысота)`
но и видео `![класс и стили]`&#8203;`(путь-к-видео.webm =ШиринаxВысота)`

Также больным местом является трансклюзия других markdown-документов — то что есть во всех практически остальных разметках  (LaTeX/SGML Docbook/MediaWiki/RST/…) тут из коробки нет. А включать хочется не только Markdown-документы, 
но и какие-то проектные артефакты, типа вырезок из файлов конфигов, логов, 
и немаловажное — включение таблиц (включая форматирование и раскраску), которых проще держать и вести в CSV или XLXS, потому что таблицы в Markdown все-таки боль.

#### Трансклюзия Markdown-документов

Такую же «трансклюзию», мы тоже получаем, расширяя семантику «включения»
`![класс и стили]`&#8203;`(путь-к-markdown-документу.md)`
- Причем если указывать абсолютный путь, мы получим включение относительно папки проекта `${workspaceFolder}`


#### Включение таблиц

Поместите ссылку-включение на локальный CSV или XLSX в отдельный абзац. 
Путь отсчитывается от Markdown-файла, в котором записана ссылка.

<pre>`!&#91;rows=0;-3:, cols=0;2:4, trans](./current-portfolio.csv)

!&#91;sep=semicolon, header=none](./measurements.csv)

!&#91;sheet="Портфель, EUR", rows=0:5, styles](./portfolio.xlsx)`</pre>

- `rows` и `cols` выбирают строки и столбцы исходной таблицы, условно как питоновые слайсы. 
    - индексы начинаются с нуля, правая граница среза исключается, отрицательные индексы считаются с конца. 
    - `;` соединяет выборки в указанном порядке, но повторяющиеся индексы попадают в результат один раз.
- если выбрана строка `0`, её ячейки служат заголовками.
    - `header=none` делает их обычными ячейками.


-  Флаг `trans` меняет строки и столбцы местами после выборки. 
    - В первом примере слева получатся названия полей, справа — значения трёх последних записей.

- Для CSV используется UTF-8. Разделитель по умолчанию — запятая. 
    - доступны `sep=comma`, `sep=semicolon`, `sep=tab` и `sep=dblquote`
- Для XLSX по умолчанию берётся первый лист. 
    - Параметр `sheet` выбирает лист по имени. 
    
- Даты и числа выводятся с учётом формата ячейки, а формулы — с последним сохранённым результатом. `⁇` — результат отсутствует. 
- Флаг `styles` приносит из XLSX таблиц,  жирный шрифт, курсив, горизонтальное выравнивание и явно заданные RGB-цвета текста и сплошной заливки.
- После обновления включаемых файлов, обновляется и предпросмотр.
- Для эффективности вырезки кэшируются в `.vscode/.cache/md-laconism/`.

### Включение текстового файла как блока кода

Также, как с таблицами, держите включение отдельным абзацем, и относительный путь считается от самого вложенного файла. Сохраняет отступы, пустые строки и символы Markdown. 

<pre>
!&#91;](./example.txt)

!&#91;](./diagram.py)

!&#91;type=yaml](./config.yaml)

!&#91;type=mermaid](./diagram.generated)

!&#91;type=text](./diagram.py)
</pre>

- Язык подсветки 
    - по расширению файла
        - Python для `.py` и YAML для `.yml`…
    - или по имени
        - `Makefile`, `Dockerfile`…
    - иначе без подсветки, или явно указать `type=язык` 
    (выбирает тот же обработчик, что и у блока кода Markdown)
        - `type=mermaid` превращает исходник в диаграмму, 
        - `type=text` показывает даже Python без раскраски
- Поддерживаются UTF-8 и UTF-16 с маркером BOM 

Также, как с включением таблиц, есть параметры 
`rows` и `cols`, только теперь имеются в виду строки и колонки текстового файла — это удобно чтобы включать вырезки-примеры из больших логов или конфигов.
- Пустые строки учитываются. 
- Завершающий перевод строки дополнительной строки не создаёт.
- Для `cols` единица счёта — кодовая точка Unicode. 
- Табуляция занимает одну позицию. 
- В короткой строке отсутствующие позиции пропускаются. 
- Подсветка применяется к готовой выборке.

<pre>!&#91;rows=10:15](./example.py)

!&#91;type=text, rows=0;-3:, cols=8:](./server.log)</pre>

- Первый пример покажет строки с 11-й по 15-ю с подсветкой Python. 
- Второй — первую строку и три последние, начиная с девятого символа каждой строки. 

Для Mermaid достаточно одного обработчика в предпросмотре. В VS Code со встроенной поддержкой диаграмм используйте её. В версиях VS Code и code-server без встроенной поддержки установите `bierner.markdown-mermaid`.


#### Гиперлинковка на соседние файлы

Еще частой необходимостью является автоматическая гиперлинковка на лежащие рядом markdown-документы и другие программные артефакты.
Для этого, для «кодовых» литералов, начинающися с `./` типа 
`./путь-к/какому-то/артефакту.py` — автоматически превращается в гиперссылку относительно текущего пути.

А если ссылка идет на markdown-документ, то ссылка типа
`./путь-к/какому-то/артефакту.md` (которую уже можно сделать активной в самом документе с помощью других расширений vscode/code-server/code-oss), в HTML превращается в ссылку
`./путь-к/какому-то/артефакту.html`, позволяя из набора markdown документов сделать связанную техническую документацию или базу знаний.
